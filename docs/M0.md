# M0 - Green Baseline, Coordination Substrate, Evidence Discipline

M0 is not a feature milestone. It is the milestone that makes every later
milestone trustworthy: the repository state is known, the verification loop is
reproducible, coordination artifacts exist, and no claim in the roadmap stands
without evidence.

## Entry criteria (all satisfied)

- Repository state analysed from Git, not from prior session memory.
- Local verification environment reproducible in a virtualenv.
- Full test suite executed with a recorded result.

## Explicitly out of scope for M0

- Closing `docs/V1_RELEASE_GATE.md`. Two gate items require evidence this
  environment cannot produce: an observed release-provenance execution
  (workflow dispatch is denied for the connected integration) and an audited
  production AEAD provider.
- New product features in Phases 2-11. Those are M3+ work and must not be
  started while the release blockers are simply being carried forward.

## Why M0 is worth a milestone

The defect that motivated it is instructive: `fs_overlay/policy.py` shipped with
a syntax error, so the module raised `SyntaxError` on import, while the ordinary
CI matrix stayed green because nothing imported it. A green suite over an
unknown surface is not a baseline. M0 makes the surface itself part of the
tested contract and makes every completion claim checkable.
